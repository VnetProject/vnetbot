# ربات فروش نمایندگی پنل (PasarGuard Reseller Bot)

## معماری
- **aiogram v3.26+** برای ربات تلگرام (از Bot API 9.4 برای رنگ واقعی دکمه‌ها و ایموجی پرمیوم استفاده می‌شود)
- **MySQL + SQLAlchemy (async)** برای دیتابیس
- **APScheduler** برای محاسبه و کسر هزینه مصرف هر ساعت
- **کتابخانه `pasarguard`** برای اتصال به API پنل PasarGuard

---

## 🚀 نصب سریع روی VPS (مثل اسکریپت‌های نصب معروف)

بعد از اینکه این پروژه را در گیت‌هاب خودتان آپلود کردید (پایین توضیح داده شده)، کافیست این یک خط را روی سرور Ubuntu اجرا کنید:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/USERNAME/REPO/main/install.sh) install
```

(به‌جای `USERNAME/REPO` آدرس ریپوی خودتان را بگذارید)

این اسکریپت به‌طور خودکار:
1. پیش‌نیازهای سیستمی (python3, venv, pip, mysql-server, git) را نصب می‌کند.
2. سورس را دریافت/آپدیت می‌کند.
3. دیتابیس MySQL و کاربر آن را می‌سازد (پسورد رندوم امن تولید می‌کند مگر خودتان وارد کنید).
4. یک virtualenv پایتون ساخته و کتابخانه‌ها را نصب می‌کند.
5. توکن ربات و آیدی عددی ادمین را از شما می‌پرسد و config.json را می‌سازد.
6. یک سرویس systemd می‌سازد تا ربات همیشه در پس‌زمینه اجرا بماند و بعد از ری‌بوت سرور هم بالا بیاید.

### مدیریت بعد از نصب
```bash
bash install.sh status     # وضعیت سرویس
bash install.sh logs       # مشاهده لاگ‌های زنده
bash install.sh restart    # ری‌استارت
bash install.sh update     # دریافت آخرین نسخه از گیت‌هاب + نصب مجدد کتابخانه‌ها + ری‌استارت
bash install.sh uninstall  # حذف کامل سرویس و فایل‌های ربات (دیتابیس حذف نمی‌شود)
```

> نکته: برای اجرای install.sh باید با کاربر root یا sudo باشید.

### آپلود پروژه در گیت‌هاب (اگر تازه می‌خواهید انجام دهید)
```bash
cd pasarguard_bot
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```
سپس داخل فایل install.sh، مقدار REPO_URL را به آدرس ریپوی خودتان تغییر دهید و دوباره push کنید تا لینک نصب یک‌خطی بالا کار کند. فایل .gitignore طوری تنظیم شده که config.json و پسوردهای دیتابیس هرگز به گیت‌هاب پوش نشوند.

## نصب دستی (روش قدیمی/جایگزین)

```bash
sudo apt update && sudo apt install -y python3 python3-venv python3-pip mysql-server git

sudo mysql -e "CREATE DATABASE resellerbot CHARACTER SET utf8mb4;"
sudo mysql -e "CREATE USER 'resellerbot'@'localhost' IDENTIFIED BY 'YOUR_STRONG_PASSWORD';"
sudo mysql -e "GRANT ALL PRIVILEGES ON resellerbot.* TO 'resellerbot'@'localhost';"
sudo mysql -e "FLUSH PRIVILEGES;"

cd pasarguard_bot
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

python3 install.py     # توکن، آیدی ادمین، اطلاعات دیتابیس، پورت را می‌پرسد
python3 main.py
```

برای اجرای دائمی، از بخش setup_systemd در install.sh الگو بگیرید یا خودتان یک سرویس systemd مشابه بسازید.

## بعد از اجرا - راه‌اندازی اولیه در تلگرام
1. در تلگرام به ربات دستور /admin را بزنید (فقط آیدی عددی که موقع نصب وارد کردید دسترسی دارد).
2. از «🖥 پنل‌ها» حداقل یک پنل PasarGuard اضافه کنید. بلافاصله بعد از وارد کردن پسورد، ربات خودش وصل شدن به پنل را تست می‌کند و نتیجه (✅ موفق / ❌ ناموفق + دلیل خطا) را نشان می‌دهد. هر وقت هم خواستید از دکمه «🔌 تست اتصال» داخل جزئیات پنل دوباره تست بگیرید.
3. از «📦 پلن‌ها» پلن بسازید - در مرحله انتخاب رول ادمین، ربات لیست رول‌های واقعی موجود در همان پنل (مثلاً owner/administrator/operator) را مستقیماً از پنل می‌خواند و دکمه‌ای نشان می‌دهد تا انتخاب کنید؛ اگر به هر دلیل نتوانست بخواند، به ورود دستی نام رول برمی‌گردد.
4. از «⚙️ تنظیمات» شماره کارت، ولت TON، نرخ دلار، محدوده شارژ و حجم/مدت تست (اکنون به مگابایت، نه گیگابایت) را تنظیم کنید.
5. از «📣 کانال‌ها» کانال جوین اجباری و کانال گزارشات را اضافه کنید (ربات باید در آن‌ها ادمین باشد).
6. از «📝 متن‌های ربات» متن خوش‌آمدگویی/قوانین/سوالات متداول را ویرایش کنید.
7. از «🎨 دکمه‌ها» رنگ، متن و ایموجی پرمیوم هر دکمه اصلی را جداگانه تنظیم کنید.

## 🎨 رنگ واقعی دکمه‌ها و ایموجی پرمیوم (Bot API 9.4)
تلگرام در آپدیت Bot API 9.4 واقعاً امکان رنگ‌بندی دکمه‌های اینلاین (style: آبی/سبز/قرمز/پیش‌فرض) و گذاشتن یک ایموجی پرمیوم قبل از متن دکمه (icon_custom_emoji_id) را اضافه کرده - نسخه قبلی این پروژه هنوز از این قابلیت استفاده نمی‌کرد و به‌جایش با ایموجی دایره‌ای رنگی شبیه‌سازی می‌شد؛ این نسخه از رنگ واقعی و ایموجی پرمیوم واقعی استفاده می‌کند.

- از «🎨 دکمه‌ها» در پنل مدیریت، هر دکمه اصلی (خرید/کیف پول/.../بازگشت) را انتخاب و رنگ آن را با یک تپ تغییر دهید.
- برای ایموجی پرمیوم، کد وارد نمی‌کنید - داخل چت با ربات، خودِ ایموجی پرمیوم را می‌فرستید (باید خودتان Telegram Premium داشته باشید تا هنگام ارسال، ایموجی به‌صورت "custom emoji" شناسایی شود؛ ربات آیدی آن را خودش از پیام استخراج می‌کند).
- دکمه «بازگشت» که در همه صفحات تکرار می‌شود، یک تنظیم مشترک دارد (کلید back) که همه‌جا یکسان اعمال می‌شود.

## چند ایموجی پرمیوم داخل یک متن
در «📝 متن‌های ربات»، وقتی متن جدید یک بخش (مثلاً خوش‌آمدگویی) را می‌فرستید، می‌توانید همان‌جا، دقیقاً کنار هر کلمه‌ای که خواستید، ایموجی پرمیوم را هم داخل همان پیام بچسبانید - مثلاً:

```
(ایموجی پرمیوم) سلام به ربات خوش اومدی (ایموجی پرمیوم دیگر)
```

ربات پیام شما را با فرمت HTML (تگ tg-emoji) ذخیره می‌کند، پس هر چند ایموجی پرمیوم که در متن باشد به‌درستی نمایش داده می‌شود.

## 🐛 باگ‌هایی که در این نسخه رفع شد

1. **«اصلاً پنل نمی‌ساخت / موقع وارد کردن پسورد کار نمی‌کرد»**: علت اصلی یک خطای MissingGreenlet در SQLAlchemy async بود - کد قبلی بعد از بستن session سعی می‌کرد رابطه‌های ORM (plan.panel, reseller.panel, reseller.user, ...) را lazy-load کند که در SQLAlchemy async ساپورت نمی‌شود. همه این نقاط الان با fetch مستقیم و صریح جایگزین شده‌اند (utils/billing.py, bot/handlers/buy_panel.py, bot/handlers/my_panels.py, bot/handlers/admin/plan_admin.py).
2. **خطای «message is not modified»**: وقتی روی دکمه‌ای مثل «بروزرسانی» می‌زدید و محتوای پیام دقیقاً همان قبلی بود، تلگرام خطا برمی‌گرداند و کل هندلر کرش می‌کرد. الان این خطا به‌صورت سراسری در bot/patches.py بی‌خطر می‌شود.
3. **«پیام برای ادمین چه در پشتیبانی چه در ارسال رسید نمی‌رفت»**: دو علت داشت:
   - اگر کانال گزارشات تنظیم نشده بود یا ربات در آن ادمین نبود، پیام فقط silently با except/pass گم می‌شد. الان علاوه بر کانال گزارشات، همیشه مستقیماً هم به آیدی عددی ادمین اصلی (OWNER_ID) ارسال می‌شود (notify_admins در bot/handlers/common.py) - یعنی حتی بدون تنظیم هیچ کانالی، پیام‌ها به دست ادمین می‌رسند.
   - چون پیام‌ها با parse_mode پیش‌فرض HTML ارسال می‌شدند، اگر متن کاربر کاراکترهایی مثل < یا & داشت، کل ارسال با خطای «entities را نمی‌شود parse کرد» رد می‌شد. الان parse_mode پیش‌فرض ربات None است و فقط متن‌های خودِ ادمین (خوش‌آمدگویی/قوانین/...) صراحتاً با HTML ارسال می‌شوند.
4. **دکمه «تست اتصال» پنل**: موقع افزودن پنل، ربات بلافاصله اتصال را تست کرده و نتیجه را نشان می‌دهد؛ یک دکمه «🔌 تست اتصال» هم در جزئیات هر پنل برای تست مجدد اضافه شد.
5. **دکمه بازگشت/انصراف در همه‌ی مراحل ورودی متن**: همه‌ی پیام‌هایی که منتظر پاسخ متنی شما هستند (از تغییر رنگ دکمه تا ارسال رسید و تنظیم پسورد) حالا یک دکمه بازگشت/انصراف دارند که شما را به منوی مربوطه برمی‌گرداند و state را پاک می‌کند.
6. **حجم تست به مگابایت**: به‌جای گیگابایت، الان مگابایت است (نام ستون دیتابیس عوض نشده تا نیازی به migration نباشد، فقط واحد نمایش/محاسبه در کل UI و در ساخت کانفیگ تست به MB تغییر کرده).
7. **دستور اختصاصی هر دکمه**: /new, /wallet, /myplans, /test, /faq, /rules, /support اضافه شد (جدول بالا).
8. **رول ادمین پاسارگارد از خود پنل خوانده می‌شود**: به‌جای تایپ دستی نام رول، ربات با get_admin_roles سعی می‌کند لیست واقعی رول‌های پنل را بخواند و دکمه انتخاب نشان دهد.

## نکات مهم که هنوز باید روی VPS واقعی خودتان تأیید کنید

این‌ها به نسخه دقیق SDK پاسارگارد نصب‌شده روی سرور شما بستگی دارند (با TODO در کد مشخص شده‌اند):

1. **utils/panel_client.py → create_reseller_admin**: به ترتیب فیلدهای role_id سپس role را روی AdminCreate امتحان می‌کند. برای اطمینان کامل روی VPS اجرا کنید:
   ```bash
   source venv/bin/activate
   python3 -c "from pasarguard import AdminCreate; print(AdminCreate.model_fields)"
   ```
   و در صورت نیاز نام فیلد را در همان تابع اصلاح کنید.

2. **utils/panel_client.py → get_admin_roles**: چند نام متد محتمل (get_admin_roles, get_all_admin_roles, admin_roles) را روی کلاینت امتحان می‌کند. اگر هیچ‌کدام کار نکرد (لیست خالی برگرداند)، ربات به‌طور خودکار به ورود دستی نام رول برمی‌گردد - در آن صورت نام متد درست را با همین فرمان پیدا کنید:
   ```bash
   python3 -c "from pasarguard import PasarguardAPI; print([m for m in dir(PasarguardAPI) if 'role' in m.lower()])"
   ```

3. **get_admin_usage_bytes**: فرض شده get_admins() آبجکتی با فیلد used_traffic برمی‌گرداند. اگر اسم فیلد چیز دیگری بود، همین یک خط را در utils/panel_client.py اصلاح کنید.

4. **ایموجی پرمیوم روی دکمه**: icon_custom_emoji_id طبق مستندات Bot API 9.4 نیاز دارد صاحب ربات (شما) Telegram Premium داشته باشد تا ایموجی به کاربران نمایش داده شود؛ در غیر این صورت ممکن است نمایش داده نشود یا تلگرام خطا بدهد - در آن صورت رنگ (style) همچنان بدون مشکل کار می‌کند.
